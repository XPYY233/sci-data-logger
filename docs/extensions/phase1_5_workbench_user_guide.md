# Phase 1.5 用户端使用教程：外挂式个性化工作台

## 你现在能做什么

`workbench` 是一个完全外挂的轻量网页入口，用来把已有湿实验个性化能力变得更容易使用：

- 在共享电脑上切换当前用户；
- 上传湿实验记录；
- 选择实验模板与仪器模板；
- 直接查看系统识别结果、术语归一结果和个性化缺失项；
- 在网页里维护自己的基础规则，而不必手改 JSON。

它不会修改主项目核心代码，也不会接管 drylab 模块。

---

## 1. 启动工作台

在项目根目录运行：

```bash
python -m extensions.workbench.cli serve
```

默认地址：

```text
http://127.0.0.1:8015/workbench
```

---

## 2. 第一次进入时

首页先做两件事：

1. 选择当前是谁在使用；
2. 如果还没有你的用户，直接新建一个。

工作台会记住你上次选择的用户，方便共享电脑上的日常切换。

---

## 3. 分析一份湿实验记录

在“新建记录”页：

1. 填写实验 ID；
2. 上传实验本图片 / PDF / 仪器文件；
3. 选择需要的课题组模板、实验模板、仪器模板；
4. 点击“开始分析”。

结果页会分成四块：

- 系统识别到了什么；
- 系统按你的习惯做了哪些理解；
- 当前还缺什么；
- 建议你下一步补什么。

例如，你的记录里写了 `预烧`，如果当前模板把它映射为 `calcine`，页面会直接展示：

```text
预烧 → calcine
```

---

## 4. 维护“我的规则”

网页首版支持修改的个人字段包括：

- 显示名；
- 术语别名；
- 样品编号模式；
- 个人必填字段；
- 偏好字段；
- 手写习惯备注。

为了避免多人共用时把共享规则改乱，首版**不开放**以下内容的网页编辑：

- 课题组模板；
- 实验模板；
- 仪器模板。

这些仍由共享模板或 CLI 流程维护。

---

## 5. 它和现有 CLI 的关系

- `extensions.personalization` 仍然负责真正的规则与 profile；
- `extensions.workbench` 只是更友好的网页入口；
- CLI 和网页会读写同一套本地个性化数据：

```text
.local_data/extensions/personalization/
```

因此你可以：

- 先用 CLI 建立配置；
- 再用网页做日常使用与基础修改；
- 两边不会冲突。

---

## 6. 为什么它仍然是“外挂”

当前阶段继续遵守：

- 不改 `src/sci_data_logger/`；
- 不改主项目 schema；
- 不把 workbench 逻辑塞进主 API；
- 通过已有公开能力与 ID 进行松耦合协作。

这保证了：

- 你的工作可以和其他人的扩展并行推进；
- 后续 drylab、结果分析或其他外挂可以独立演化；
- 未来如果需要统一入口，也能再按成熟后的边界接入。
